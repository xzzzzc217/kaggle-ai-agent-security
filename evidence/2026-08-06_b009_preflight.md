## 3. Hypothesis

B008's current best score came from preserving the B005 replay-safe tail and
slow-row four-endpoint frame plan while reducing classification overhead. B009
tests a lower-level search-throughput mechanism: if slow-row frame candidates
need exactly four tool calls to validate all intended endpoints, then probing at
four hops should preserve the validated candidate shape while avoiding any extra
wrap-up generation from an eight-hop live fill.

This is structurally different from B006 threshold routing, B007 fast/plain
direct burst, and B008 classification-batch sizing. It does not change candidate
messages; it only changes the live validation hop cap used before returning the
same candidate messages for grader replay.

## 5. Risks and falsifiability

- B009 may be neutral if hidden `env.interact(..., max_tool_hops=8)` already
  stops immediately after the same four slow-row tool calls.
- B009 can underperform if the hidden validator needs a final response after the
  fourth tool call for more stable traces.
- Because `REPLAY_COST_COEF` remains `1.0`, B009 intentionally avoids a second
  cost-model variable; if four-hop validation still underestimates replay wall
  materially, it can return too many candidates and lose score.
- If the B008 gain is dominated by candidate-message choice rather than live-fill
  throughput, probe4 may not improve the Public Score.
