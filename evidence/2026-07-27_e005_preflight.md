## 选择依据

E002 把本地机制覆盖改善转化成了更低的真实 public score `0.060`，因此本实验不沿用
E002 的新颖度轮转、签名去重或每签名上限。E003/E004 已经占用为早期原型和 SDK
契约实验编号，正式实验使用新编号 E005，避免覆盖历史身份。

SDK 3.1.2 自带的 Go-Explore attacker 使用公开 prompt bank、snapshot archive 和
基于 cell novelty 的搜索，比 E001 的九条手写候选覆盖更大的多步链路空间。但在本地
10 秒 scorer-equivalent 评测中，未包装版本会用满内部 `time_budget_s`，随后被外层
评分器判定：

```text
attack generation exceeded its time budget
```

5% 退出余量仍不足，因为一个 12 分支批次可以跨过外层截止时间。SDK 源码还明确提示，
长预算下每个 archive cell 保存完整 snapshot，峰值内存会随 novel cell 数增长。

## 假设与主要变量

**假设**：把 E001 的固定手写候选搜索替换为竞赛 SDK 3.1.2 的 Go-Explore 搜索，并
用确定性的墙钟和内存边界保证 generation 返回，可以发现更多可由 evaluator 重放的
高价值 cell，使 E005 public score 严格高于 E001 的 `0.075`。

**主要变量**：搜索策略。

- E001：固定九组候选消息，按预定顺序执行。
- E005：使用 SDK Go-Explore 的 prompt bank、snapshot archive、cell novelty 和
  reward hint 选择。
- E005 不使用 E002 的自定义签名归一化、轮转或 finding 上限。
- 可靠性边界不是独立评分优化：委托搜索最多使用 scorer 总预算的 80%，且不超过
  900 秒；`max_steps` 和 `max_tool_hops` 原样传递。

代码只通过竞赛提供的离线 environment 和 SDK prompt bank 工作，不增加互联网访问、
凭证或非 fixture 目标。

## 结果判定

E005 public score 为 `0.000`，比直接对照 E001 的 `0.075` 低 `0.075`。根据出分前
固定的判定表，这一结果属于“拒绝该候选”，不支持有界 SDK Go-Explore 改善真实评分
的假设。

从 submission 创建到首次观测完成约 1 小时 2 分钟，其中包含 Kaggle 队列等待，不能
解释为算法运行时或 GPU 配额消耗。CLI 没有返回 private score、候选数量、重放日志或
精确执行时长。

真实 public score `0.000` 与预注册阶段确定性 agent 的本地 `0.00` 数值都为零，但
证据来源完全不同：前者是隐藏 competition rerun 的真实榜单结果，后者只是公开 fixture
机制检查。不能用这种数值一致反推本地 agent 能预测隐藏评测。

`0.000` 说明最终没有可计分贡献，但仅凭 CLI 不能区分以下情况：

- Go-Explore 没有返回候选；
- 返回候选但 evaluator 重放后没有 predicate；
- 候选触发了 predicate 但未形成可计分 cell；
- 目标模型、guardrail 或时间/内存边界使搜索失效。

决策：

- 拒绝 E005，不重复提交，也不修改预注册门槛。
- 不继续做 Go-Explore 参数消融，除非先获得能区分候选生成与重放失败的诊断证据。
- 下一实验回到真实分数 `0.075` 的 E001 手写候选路线，优先隔离新增攻击模板覆盖，
  而不是再次整体替换搜索器。
