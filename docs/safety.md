# Safety boundary

本项目只研究竞赛主办方明确授权的离线安全基准。学生身份和善意目的不能替代技术边界，因此使用下面的可核验约束控制风险。

## 允许范围

- Kaggle 比赛提供的 `aicomp_sdk`、fixture、模型与隐藏 evaluator；
- 本地构造的纯模拟环境；
- 比赛定义的合成秘密与测试地址；
- 对攻击搜索、轨迹重放、guardrail 评测和防御建议的研究；
- 在比赛规则允许的范围内公开可复现结果。

## 禁止范围

- 真实网站、API、邮箱、文件系统、组织内网或个人设备；
- 真实凭证、个人数据、商业秘密或从第三方获得的敏感数据；
- 对非竞赛模型服务进行越权、绕过、探测或批量攻击；
- 把竞赛 prompt、工具链或 exploit 迁移到真实目标；
- 规避访问控制、速率限制、验证码、付费限制或平台安全机制。

## 工程控制

1. 网络目标只允许 RFC 保留的 `example.com` 子域与 `.invalid` 保留域名。
2. 所有秘密必须是显式合成值，例如 `SECRET_MARKER` 或 starter 中的测试字符串。
3. 本地 runner 默认禁网；任何出现真实域名、IP、邮箱或 Token 形态的输入都应测试失败。
4. 不把 `kaggle.json`、Token、Notebook secret 或原始凭证写入 Git、日志或聊天。
5. 发现比赛 SDK 可能访问真实资源时立即停止该路径，保存最小证据并向主办方报告。
6. Working Note 重点描述基准机制、可复现性和防御启示，不提供面向真实系统的操作手册。

## 风险处置

| 风险 | 解决方案 |
|---|---|
| prompt 意外包含真实目标 | 提交前运行 allowlist 扫描，只允许保留域和 fixture 标识 |
| 日志泄露 Token/秘密 | 默认脱敏；凭证文件加入 `.gitignore`；禁止粘贴 Token |
| 研究结果可被迁移滥用 | 只发布基准限定代码，删去真实目标适配层，加入防御与限制说明 |
| 私有 guardrail 诱导过拟合 | 使用机制多样性和双模型验证，不尝试探测主办方外部系统 |
| SDK 出现异常联网行为 | 禁网复现、停止实验、向 Kaggle/主办方负责任披露 |

任何不确定行为都按“是否仍完全发生在竞赛离线沙盒内”判断；答案不是明确的“是”时，不执行。
